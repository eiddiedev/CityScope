# CityScope：没人能赢下的超级工厂

> **政企互动多 Agent 决策推演场**  
> 成都高新区与重庆两江新区，一场具身智能产业项目争夺战

**一句话介绍：** CityScope 把招商决策拆成 12 个有独立目标、权限和私有信息的行为 Agent，以及 4 个确定性规则 Service；通过 OR-Tools、TOPSIS、BATNA、制度门与因果回放，让政府与企业在签约前看见一项政策在不同利益主体和不同时间尺度下的真实代价。

**在线演示：** [cityscope-demo.vercel.app](https://cityscope-demo.vercel.app)  
**代码仓库：** [github.com/eiddiedev/CityScope](https://github.com/eiddiedev/CityScope/tree/work/integration)

![CityScope 双城 2.5D 决策沙盘](https://raw.githubusercontent.com/eiddiedev/CityScope/work/integration/frontend/artifacts/cityscope-twin-static-frame.png)

> **重要声明**  
> 本项目使用成都高新区、重庆两江新区的公开产业特征构造反事实实验场景。企业“星岚机器人”、30 亿元投资、1200 个岗位、34% 约束性订单、政策金额及全部具体事件均为虚构压力测试参数，不代表真实政策，不预测现实决策。

## 一、目标用户与核心问题

### 1. 目标用户

- **地方政府与园区管理者：** 在招商政策签发前，预演财政、产业、就业、审计和公众反应。
- **企业战略与政府事务团队：** 比较单城落地、双城分工、缩小规模和退出等路径。
- **投资机构与产业研究者：** 识别订单、现金流、政策兑现和产能利用风险。
- **高校与公共政策教学：** 将抽象的政企博弈变成可干预、可回放、可验证的实验。

### 2. 核心问题

现实招商不是“输入材料，让一个模型给出最优城市”。同一项目中：

- 招商部门希望尽快签约；
- 财政部门担心补贴无法兑现；
- 地方负责人同时承担就业、产业和政府信用；
- 企业 CEO 追求增长，CFO 保护现金流；
- 投资机构要求订单确定性；
- 上级协调方希望避免两地重复补贴；
- 居民、中小企业和人才承担公共资源与挤出效应。

这些主体拥有**不同目标、不同权限、不同信息和不同时间尺度**。把它们压缩成一个聊天模型，会得到语言流畅但责任边界模糊的建议。

> **CityScope 要回答的不是“谁赢了招商”，而是：谁签了字、依据什么、改变了什么，以及两年以后这项政策是否仍然成功。**

## 二、方案与赛题的对应关系

本项目对应赛题三“政企互动 Agent 推演场”。赛题要求用智能体模拟企业、政府、园区、投资机构和公众在招商、政策、审批、补贴、产业落地、就业带动与城市发展中的决策、协商、博弈和演化。

| 赛题关键词 | CityScope 对应能力 |
|---|---|
| 政企互动 | 成都、重庆、企业、资本与上级部门分层决策 |
| Agent 推演 | 12 个行为 Agent 独立观察、选择、谈判与签发 |
| 政策与审批 | PolicyPack、审计、修订、撤回和承诺账本 |
| 资源配置 | OR-Tools/枚举求解财政、土地、能源、厂房、人才约束 |
| 决策与博弈 | 多角色 TOPSIS、BATNA 和保留效用 |
| 演化 | 尽调冲击、重新协商、12/24 月履约影响 |
| 可验证性 | Gate、StateDelta、DecisionReceipt、causeId 与 A/B 分叉 |

## 三、反事实场景：为什么这是一场真正的博弈

虚构企业“星岚机器人”提出建设西部研发总部、机器人训练中心、智能工厂与上下游基地，宣称总投资 30 亿元、约 1200 个直接岗位。成都和重庆都希望承接，但两座城市争取的并不是同一件事。

| 维度 | 成都高新区实验画像 | 重庆两江新区实验画像 |
|---|---|---|
| 核心优势 | 算法人才、研发、高校、总部吸引力 | 制造基础、供应链、生产空间、物流 |
| 主要诉求 | 研发总部、高端人才、产业品牌 | 智能工厂、产值、供应链 |
| 主要风险 | 只有总部，没有真实产能 | 为不确定产能投入过多资源 |
| 政策工具 | 研发、人才、场景开放 | 厂房、设备、供应链与生产支持 |

企业则希望利用两地竞争获得更多前置资源。第一轮之后，尽调规则服务披露：**约束性订单只有 34%，企业现金流约能支撑一年**。此时“更高补贴”不再天然等于“更优方案”。

系统允许四类正式终局自然产生：

1. **成都主导**：企业接受经审计的成都最终政策，重庆撤回或关闭要约。
2. **重庆主导**：与成都主导对称。
3. **政府协调分工**：两地分别接受真实功能拆分，审计通过，董事会接受联合方案。
4. **项目退出**：两城正式撤回，企业董事会终止或转向其他区域。

终局之后继续计算 12/24 月影响，因此“获得项目”和“政策长期成功”是两个不同维度。

## 四、16 个主体：不是 16 个模型轮流聊天

当前系统包含 **12 个行为 Agent + 4 个确定性规则 Service**。语言模型只处理适合语言和判断的任务，预算、权限、资源、尽调和长期影响由可信代码约束。

![CityScope 16 主体组织剖面](https://raw.githubusercontent.com/eiddiedev/CityScope/work/integration/frontend/artifacts/cityscope-16-actor-organization.png)

### 1. 12 个行为 Agent

| 层级 | 主体 | 独立职责与边界 |
|---|---|---|
| 区域层 | 区域协调 Agent | 寻找互补与帕累托改进，但不能替地方签约 |
| 区域层 | 政策监督 Agent | 审计预算、重复补贴、兑现条件；不能代替负责人 |
| 成都 | 招商 Agent | 提案与产业收益；只有建议权 |
| 成都 | 财政 Agent | 控制前置支付与财政红线；只有建议权 |
| 成都 | 负责人 Agent | 汇总部门意见，签发、修订或撤回政策包 |
| 重庆 | 招商 Agent | 关注工厂、产值、供应链；只有建议权 |
| 重庆 | 财政 Agent | 关注产值确定性与厂房利用；只有建议权 |
| 重庆 | 负责人 Agent | 汇总部门意见，签发、修订或撤回政策包 |
| 企业 | CEO Agent | 追求扩张、品牌和控制权；不能签署最终回应 |
| 企业 | CFO Agent | 关注现金跑道与刚性承诺；不能签署最终回应 |
| 企业 | 董事会 Agent | 收齐 CEO/CFO 意见后作出正式企业决定 |
| 资本 | 投资机构 Agent | 独立判断融资，不替企业或城市选择 |

### 2. 4 个确定性 Service

| Service | 为什么不用 LLM |
|---|---|
| 人才与中小企业代表 | 以群体立场表达态度，并确定性计算住房、本地采购与挤出分布 |
| 居民代表 | 以居民视角表达支持或反对，并计算就业、财政公平与公共资源压力 |
| 尽调规则服务 | 按阶段和受众范围核验、披露事实，避免模型随意“创造真相” |
| 世界与资源规则服务 | 更新资源、承诺、履约进度和 12/24 月影响 |

### 3. 为什么必须拆开

- **部门意见不等于政府最终意见。** 招商和财政可以冲突，只有负责人能签发。
- **政府承诺受到审计和资源红线约束。** 语言模型不能越权修改世界。
- **企业内部也有治理结构。** CEO/CFO 提议，董事会才有最终权力。
- **协调不等于替大家做决定。** 区域协调方只能提出方案，两地和企业必须分别接受。

## 五、核心功能与三层交互

### 1. 战略层：双城 2.5D 沙盘

建筑对应真实决策主体。某个 Agent 行动时，镜头跟随对应建筑，展示其建议、数值变化和项目在两城之间的倾向。底部竞争带同步呈现政策吸引力、财政可持续、研发人才、制造供应链和资源兑现能力。

### 2. 组织层：16 主体组织剖面

点击城市或组织即可查看上下级关系、建议权、签发权、审计权、私有事实和红线。内部冲突通过部门辩论与政策包合成表现，而不是隐藏在一段总回答里。

### 3. 证据层：Agent X-Ray 与世界分叉

点击任意变化可查看：

- Agent 当时可见的事实与私有信息；
- 目标、红线、TOPSIS 排名、BATNA 和所选 candidateId；
- Authority / Privacy / Constraint Gate；
- before / after / causeId / worldVersion；
- 同一 Checkpoint、单一变量干预后的 A/B 因果链。

## 六、AI 承担的关键任务与完整链路

![CityScope 多 Agent 完整决策流程图](https://raw.githubusercontent.com/eiddiedev/CityScope/work/integration/docs/architecture/cityscope-agent-flow.svg)

```text
世界状态与分级可见事实
        ↓
决策支持生成可行候选
        ↓
各角色 TOPSIS 排序 + BATNA/保留效用
        ↓
DeepSeek Agent 结合私有信息选择、拒绝、修订或谈判
        ↓
Authority / Privacy / Constraint Gate
        ↓
World Reducer 写入 StateDelta 与承诺账本
        ↓
DecisionReceipt + causeId + 12/24 月影响
```

### 1. DeepSeek：处理不可枚举的组织判断

DeepSeek 负责：理解角色诉求、引用当前候选、解释偏离 TOPSIS 第一名的私有理由、提出让步、回复谈判、形成可读的立场。它**不能**直接改预算、创造资源、绕过审计或指定结局。

### 2. 组合优化：回答“哪些方案做得到”

五类功能——总部、研发中心、智能工厂、供应链基地、培训中心——可分配至成都、重庆或暂缓。求解器同时处理财政、土地、厂房、能源、人才住房、企业投资上限、重复补贴和分阶段兑现约束，产生：成都单城、重庆单城、双城拆分、缩小规模和不落地方案。

- 本地完整运行使用 **OR-Tools CP-SAT**。
- Serverless 在线演示因 Python 运行时限制，使用同约束口径的确定性枚举求解并做 TypeScript 二次验证。
- 贪心启发式用于候选种子、排序与快速降级，不替代最终合法性校验。

> 组合优化回答“能不能做”，不回答“谁应该赢”。

### 3. TOPSIS：回答“为什么大家偏好不同”

同一组可行候选，由成都招商、成都财政、重庆招商、重庆财政、协调方、监督方、CEO、CFO、董事会和投资机构分别排序。权重与每个 Agent 的 Manifest 效用保持一致，避免一套评分、一套人格。

> TOPSIS 显示利益差异，但不能替 Agent 签字。Agent 若偏离第一名，必须引用候选并说明私有事实、红线或 BATNA。

### 4. BATNA：协调必须优于各自的最佳替代方案

双城方案只有在两城均保留核心功能、两城效用未跌破 BATNA 与让步预算、企业效用高于退出保留值、区域协同覆盖协调成本且资源可行时，才能进入正式协调。协调 Agent 可以修订，也可以宣布不存在帕累托可行方案。

### 5. Gate 与 Reducer：语言不能越权

每个候选动作依次通过：

- **Authority Gate**：这个角色有权做吗？
- **Privacy Gate**：引用的信息对它可见吗？
- **Constraint Gate**：预算、资源、生命周期和红线允许吗？

被拒绝动作保持原 worldVersion，并产生 **0 StateDelta**。只有通过 Gate 的正式动作才能由 Reducer 改变世界。

## 七、核心流程：两轮决策，而非预写剧情

1. 成都、重庆部门分别提出内部建议。
2. 两地负责人签发政策包 v1。
3. 政策监督审计。
4. CEO、CFO、投资机构初评。
5. 尽调披露“约束性订单仅 34%”这一压力测试事实。
6. 两地财政和招商重新评价。
7. 两地负责人分别维持、修订或撤回。
8. 决策支持重新生成单城、双城、缩小规模和退出选项。
9. 只有存在可谈判联合方案才进入区域协调，最多两轮。
10. 两地分别回应，监督方重新审计。
11. 企业董事会比较全部剩余选项并作出最终选择。
12. 系统根据正式终态分类四种结局。
13. 确定性运行 12/24 月履约与公共影响评估。

结局不是 Prompt 中的目标字段，也不是前端选项。它是正式行动链完成后，对终态的**事后分类**。

## 八、如何证明不是模拟剧情：A/B 单因实验

```text
同一初始 Checkpoint
├─ A 世界：保持原条件
└─ B 世界：只改变一个变量
             ↓
       两套 Agent 独立续演
             ↓
   首次语义行动分歧 / 首次世界状态分歧
             ↓
     不同终局，或被制度/Agent 吸收
```

每次实验记录唯一干预、共用的 Agent Profile、候选方案、首个不同动作、Gate 结果、StateDelta 和最终终局。如果行动链变化但终局相同，系统不会伪称“没有影响”，而会显示干预在哪一层被制度或 Agent 吸收。

| 供应链优势增强 | 100% | 80% | 5/5 实验世界重庆主导 |

| 项目可执行性触及红线 | 100% | 100% | 5/5 项目退出 |
| 缩减一期投资 | 100% | 60% | 5/5 实验世界成都主导 |

> **口径边界：** 50 条轨迹用于证明四种路径可达、干预可传播和制度约束有效；它不是现实政策的概率预测。默认样本没有出现退出，不代表现实退出概率为零。

### 2. 2700 次确定性机制压力测试

数据来源：`sensitivity-report.json`  
版本：`cityscope.sensitivity.v4.mechanism-validation`  
规模：6 个变量 × 9 个取值 × 50 个固定 seed = 2700 个分支

这不是 2700 次 DeepSeek 调用，而是对规则、阈值、方向性和结局可达性的机制测试。结果满足：

- 四类终局全部可达；
- 人才增强时成都主导比例单调上升；
- 供应链增强时重庆主导比例总体上升；
- 融资或项目可执行性下降时退出显著增加；
- 5 个变量能够改变终局，4 个变量达到强敏感标准；
- 2700 个分支全部合法并得到终态。

## 十一、创新点与竞争力

### 1. 从“角色扮演”升级为“制度化 Agent”

每个 Agent 都有显式权限、私有事实、效用、红线和上级关系。聊天内容本身不能改变世界，只有合规的正式行动可以。

### 2. 三层决策架构彼此不可替代

- **组合优化**：证明候选在资源上可行。
- **TOPSIS/BATNA**：解释各方偏好与谈判边界。
- **LLM Agent**：决定各方是否愿意接受，并解释偏离排名的理由。

这比“让多个角色在一个群聊里互相同意”更可控、更可验收。

### 3. 结局不等于结算

签约只是阶段性终态；12/24 月影响继续判断投资、就业、订单、产能、补贴和政府信用。系统可以呈现“赢下项目却未赢得政策效果”。

### 4. 单因世界分叉提供因果证据

相同 Checkpoint、相同 Agent Profile，只改一个变量。系统既展示不同终局，也能解释相同终局下干预被哪一层吸收。

### 5. 反直觉但不预设悲观结论

“没人能赢下”不是写死单城失败，而是：没有任何方案能同时最大化地方政绩、企业现金流、投资安全、区域收益和居民福利。赢家取决于观察的是签约当天，还是两年以后。

## 十三、后续延展空间

1. **迁移到其他政策问题：** 总部争夺、产业基金、园区更新、能源项目、重大活动和跨区域公共服务。
2. **场景配置化：** 导入不同城市画像、法定流程、财政科目和产业约束，无需重写推演引擎。
3. **真实数据接入：** 对接公开政策库、园区资源、企业尽调和财政承诺数据，并记录数据来源与时效。
4. **人类在环：** 允许真实负责人接管某个 Agent、修改权重或否决方案，系统记录影响链。
5. **更完整的政策后评估：** 接入实际履约、就业与供应链数据，持续校准 12/24 月模型。
6. **安全与治理：** 强化身份、权限、敏感事实隔离、不可抵赖审计与模型风险评测。

## 十四、项目总结

> **OR-Tools / 组合优化保证方案可行。**  
> **TOPSIS 与 BATNA 揭示利益冲突和谈判边界。**  
> **Agent 决定各方是否愿意接受，并为每一步留下可追溯证据。**

CityScope 不是替政府给出一个“正确答案”，而是把原本藏在部门、企业和时间中的冲突，变成一场可观察、可干预、可回放、可验收的决策实验。
