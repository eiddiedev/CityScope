# CityScope 3–5 分钟产品演示脚本

总路演仍为 8–10 分钟；下面只占其中约 4 分 10 秒。PPT 的问题、洞察、架构、评测和总结应使用剩余时间。

## 开场前

```bash
npm install
npm --prefix frontend install
npm run check
npm run dev
```

打开 `http://127.0.0.1:5173`，全屏。若右上角显示 `DeepSeek · LIVE`，点击开始后会真实续演；若显示 Fixture/Stub，则是经过契约验证的安全回放，不要混称为实时生成。

建议另备：浏览器刷新页、2.5D 降级页 `http://127.0.0.1:5173/?render=fallback`、60 秒录屏。

## 现场操作

| 时间 | 点击 / 操作 | 讲述重点 |
|---|---|---|
| 0:00–0:25 | 保持“双城沙盘”全景 | “这不是聊天窗口。中央是星岚机器人 30 亿元项目，左侧成都研发总部，右侧重庆智能制造；底部是可追溯的世界状态。” |
| 0:25–1:00 | 点击“设置条件并开始推演”，只改变一个变量；观察成都、重庆部门和负责人第一轮行动 | “每个政府不是一个 Agent。招商追求落地，财政控制承诺，负责人才能签发；用户改变原因，不选择结局。” |
| 1:00–1:25 | 在底部竞争带点开一次 TOPSIS/OR-Tools 证据 | “OR-Tools 先排除预算、土地、能源和重复补贴不可行方案；TOPSIS 再显示不同角色为什么排序不同，LLM 负责谈判而不是心算约束。” |
| 1:25–1:55 | 等待“订单约束性仅 34%”尽调冲击，观察指标、部门建议和政策包 v2 | “风险不是开局剧本。第二轮尽调披露后，财政和招商重新评价，负责人可缩减、修订或正式撤回。” |
| 1:55–2:45 | 若进入协调阶段，展开成都—区域协调—重庆三列谈判舞台 | “协调 Agent 不能替两城签约。它必须在六轮回复链后提交结构化功能拆分，两城分别接受让步，审计通过后董事会才能接受。” |
| 2:45–3:25 | 查看终局；再切换 A/B 世界对照 | “两个世界共享干预前历史，之后独立续演。四类标签预先定义，但结局只由撤回、审计、接受等正式世界状态成立。” |
| 3:25–3:50 | 查看 12/24 月影响 | “赢下招商不等于政策成功。我们继续计算实际投资、就业、订单转化、产能利用和财政压力。” |
| 3:50–4:10 | 点一条因果证据 | “每个视觉变化都能追到 causeId、Action、Gate 和 before/after；专业性不是 Agent 数量，而是权责、约束、算法与可复现性。” |

## 演示时不要说

- 不说“模型预测成都/重庆真实招商结果”；说“反事实机制推演”。
- 不说“当前是 DeepSeek 现场推理”，除非界面 provider 和后台健康检查确实显示 DeepSeek LIVE。
- 不说“这四个结局都是写好的剧情”；说“分类标签预先定义，产生哪个标签由终态决定”。
- 不说“16 个大模型一起聊天”；准确说“12 个行为 Agent + 4 个确定性规则/群体 Service，共 16 个可视化主体”。

## 故障降级

- 现场 Fork 超过 20 秒：继续讲签名 Fixture 的四个 Fork，并说明实时模型链路切到安全回放。
- WebGL 卡顿：使用 URL `?render=fallback` 切到 2.5D 降级，制度证据和操作不受影响。
- 后端不可用：刷新页面仍可加载已验证的签名 Fixture；不要点击 Live Fork。
- 网络或模型失败：保留 Stub / Fixture 标签，不伪装成在线推理。
