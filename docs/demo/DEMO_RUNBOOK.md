# CityScope 五分钟路演脚本

总时长严格控制在 5 分钟：HTML 叙事约 3 分 25 秒，实机重演约 1 分 20 秒，保留 15 秒缓冲。不要现场等待一轮实时模型从头跑完；使用已经完成、可回放的真实轨迹演示过程，再进入双世界对照与证据层。

## 开场前

```bash
npm install
npm --prefix frontend install
npm run check
npm run dev
```

打开 `http://127.0.0.1:5173`，全屏。若右上角显示 `DeepSeek · LIVE`，点击开始后会真实续演；若显示 Fixture/Stub，则是经过契约验证的安全回放，不要混称为实时生成。

建议另备：浏览器刷新页、2.5D 降级页 `http://127.0.0.1:5173/?render=fallback`、60 秒录屏。

## 第一段：HTML 叙事（0:00–3:25）

| 时间 | 点击 / 操作 | 讲述重点 |
|---|---|---|
| 0:00–0:25 | 第 1 屏：命题 | “一家虚构的具身智能企业承诺投资 30 亿元、创造 1200 个岗位，成都和重庆都想赢。但尽调后，约束性订单只有 34%。我们想回答的不是谁补贴更多，而是谁在承担两年后的成本。” |
| 0:25–0:45 | 第 2 屏：双城 | “成都要研发、人才和总部，重庆要工厂、产值和供应链，企业则希望利用竞争获得前置资源。三方追求的不是同一件事。” |
| 0:45–1:05 | 第 3 屏：多 Agent | “一个大模型不能同时真实代表招商、财政、负责人、企业和投资人。于是我们把组织拆成不同权限、不同信息和不同利益的主体。” |
| 1:05–1:30 | 第 4 屏：16 主体 | “系统不是 16 个模型群聊，而是 12 个行为 Agent 加 4 套确定性规则服务。Agent 负责判断和谈判，服务负责尽调、资源账本、群体反应和长期履约。” |
| 1:30–2:00 | 第 5 屏：四个工具 | “OR-Tools 回答哪些方案做得到；TOPSIS 揭示不同角色为什么偏好不同；Agent 决定是否接受、修订或撤回；Gate 检查它有没有权限、有没有越过预算和制度红线。” |
| 2:00–2:35 | 第 6 屏：不是预写剧情 | “有些系统先知道历史结果，再让 Agent 反推出一条合理路径；那证明的是能解释过去。CityScope 不告诉 Agent 谁应该赢，只让 A/B 世界改变一个条件，之后独立续演。条件改变候选，候选改变立场，正式行动才改变世界，结局最后才分类。” |
| 2:35–2:58 | 第 7 屏：数据与依据 | “我们跑了 50 条真实 DeepSeek 轨迹，四类终局全部出现，关键行动算法证据覆盖 100%，被 Gate 拒绝却改变世界为 0。另有 2700 次确定性压力测试验证方向和阈值。研究支持这类决策高风险且需要绩效条件，但不支持‘单城必然失败’。” |
| 2:58–3:15 | 第 8 屏：赢家 | “所以‘没人能赢下’不是悲观结局。某座城市可以签约成功，也可以两年后政策失败；协调和退出也各有代价。赢家取决于看签约当天，还是两年以后。” |
| 3:15–3:25 | 第 9 屏：结论并点击进入实机 | “我们的壁垒是三句话：方案做得到，冲突讲得清，结果查得回。下面只看一段真实轨迹和它留下的证据。” |

## 第二段：实机重演（3:25–4:45）

| 时间 | 点击 / 操作 | 讲述重点 |
|---|---|---|
| 3:25–3:45 | 点击“重演双世界轨迹”，让地图播放一段 Agent 行动 | “现在不是生成一段总结，而是在回放一条完整决策链。建筑对应真实主体；发言、政策包、指标和地图变化来自本轮事件。” |
| 3:45–4:05 | 让它自然播放招商、财政或协调方的 2–3 个动作 | “不同角色拥有各自目标和权限。招商只能建议，负责人才能签发；协调方只能提案，不能替两城接受。” |
| 4:05–4:28 | 直接切到证据层的“双世界对照” | “A、B 从同一 Checkpoint 出发，只改变一个变量。这里不是比较文案，而是看第一个不同动作、第一个 StateDelta 和最终结局。” |
| 4:28–4:45 | 点击一条决策证据或因果链 | “这一步能看到候选方案、TOPSIS、Agent 选择、Gate 结果和 before/after。我们用证据证明 Agent 真的驱动了世界。” |

## 收尾（4:45–5:00）

“CityScope 不预测成都或重庆会怎么做，也不替政府做决定。它让一个高风险政企决策在执行前被推演、被质疑、被比较，并且每一步都经得起追问。”

## 演示时不要说

- 不说“模型预测成都/重庆真实招商结果”；说“反事实机制推演”。
- 不说“当前是 DeepSeek 现场推理”，除非界面 provider 和后台健康检查确实显示 DeepSeek LIVE。
- 不说“这四个结局都是写好的剧情”；说“分类标签预先定义，产生哪个标签由终态决定”。
- 不说“16 个大模型一起聊天”；准确说“12 个行为 Agent + 4 个确定性规则/群体 Service，共 16 个可视化主体”。

## 故障降级

- 现场 Fork 超过 20 秒：继续讲签名 Fixture 的四个 Fork，并说明实时模型链路切到安全回放。
- WebGL 卡顿：使用 URL `?render=fallback` 切到 2.5D 降级，制度证据和操作不受影响。
- 后端不可用：刷新页面仍可加载已验证的签名 Fixture；不要点击 Live Fork。
- 网络或模型失败：保留 Stub / Fixture 标签，不伪装成在线推理。
